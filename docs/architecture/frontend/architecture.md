# Frontend

Frontend - React-приложение. Оно отображает состояние из backend и не является источником правды.

## Структура

- `src/main.jsx` - точка входа.
- `src/App.jsx` - маршрутизация.
- `src/api` - HTTP client и API-модули.
- `src/components` - переиспользуемые UI-компоненты.
- `src/content` - статический контент страниц и статей.
- `content/equipment` - единый каталог рекомендованного оборудования с датой проверки и внешними ссылками.
- `src/domain` - локальные frontend-типы и утилиты, не равные backend-доменам.
- `src/features` - прикладные состояния, hooks и contexts.
- `src/pages` - публичные страницы.
- `src/pages/app` - страницы приложения.
- `src/utils` - общие утилиты.

## Состояние

`AuthContext` хранит access token только в памяти и восстанавливает сессию через
защищённую refresh-cookie. Он охватывает публичный layout и кабинет, чтобы CTA
зависел от постоянного состояния онбординга: для завершившего пользователя CTA
скрыт, для незавершившего ведёт к продолжению настройки. SSO callback не
передаёт токен в URL. `SensorStatsContext` и `WateringSidebarContext` управляют
боковыми панелями. Данные dashboard, farm, sensors и watering загружаются через
hooks и API-модули. Backend остаётся источником readiness, связи, размещения и
состояния сценариев.

## Публичный сайт и self-service

Публичные страницы, включая `/kak-nachat/` и каталог `/oborudovanie/`, статически генерируются из тех же content-моделей, которые использует React. Для индексируемого маршрута H1, основной текст и CTA должны совпадать до и после выполнения JavaScript. Canonical, Open Graph, JSON-LD и внутренние ссылки используют конечный URL с `/`.

Приложение, административные страницы и графики загружаются лениво и не входят в начальный публичный bundle. Главное меню кабинета под `/app/` содержит «Обзор», «Конструктор фермы», «Автоматизации», «Растения» и «Настройки». В настройках находятся вкладки «Подключения», «Зоны», «Устройства» и «Профиль». Вкладка «Зоны» управляет именами, количеством и связями ферм и теплиц; Конструктор не изменяет иерархию. Старые URL кабинета только перенаправляют на новые.

Конструктор позволяет выбрать одну из ферм, показывает её общие ресурсы, теплицы, назначенные растения и доступные сценарии. Слоты добавляются пользователем по одному; кондиционер допустим у фермы и теплицы. Конструктор передаёт backend явное подтверждение переназначения занятого физического канала. Размещение растения меняется только через общую `PlantEditDialog`; Конструктор открывает ту же форму, обновляет список после сохранения и отдельным endpoint меняет только скорость полива. Групп растений в frontend нет.

Конструктор, «Автоматизации» и admin-диагностика используют один редактор
четырёх климатических порогов. Других климатических настроек в интерфейсе нет.
Скорость полива растения сохраняется в Конструкторе по Enter или потере фокуса;
при ошибке поле восстанавливает последнее серверное значение. Пользовательский
обзор переиспользует визуальные компоненты admin dashboard, показывает все
фермы и теплицы, устройства, размещённые и неразмещённые растения, климат,
запросы охлаждения, влажность, протечки, оборудование, сценарии и
предупреждения. Состояние кондиционера объясняет работу по запросам, ожидание
подтверждения команды, выключенную автоматику, неожиданное включение или
недоступность. Счётчик предупреждений строится из подробного списка, не
дублирует агрегированный запрос фермы и не учитывает неготовность выключенных
сценариев; список доступен при наведении, фокусе и касании. Обзор обновляется
раз в 30 секунд и при возврате вкладки в видимое состояние. Карточки устройств
находятся в настройках, имеют поиск, фильтр связи, не более трёх колонок, 4–6
приоритетных метрик, роли в ферме и раскрываемые технические подробности.

Профиль хранит IANA timezone. Общие форматтеры считают backend datetime без
offset значением UTC и отображают его в timezone пользователя; формы
`datetime-local`, границы дней графиков и календарные подписи используют тот
же источник. История Zigbee в обычном кабинете запрашивается по публичному UUID
координатора через tenant-scoped endpoint; admin dashboard использует
координатор-aware admin endpoint.

`VITE_SELF_SERVICE_ENABLED` управляет публичным входом в платформу. Пока флаг выключен, основной CTA ведёт на страницу раннего доступа без запуска регистрации. Сборка с включённым флагом запрещена, если в контенте приватности и условий использования не заполнены и не подтверждены данные оператора.

Продуктовые события Метрики отправляются через одну утилиту с фиксированным allowlist параметров. Email, внутренние идентификаторы, IEEE и MQTT credentials в аналитику не передаются.

## Границы

Frontend обращается к backend только через REST API. Прямой доступ к БД, MQTT broker и внутренним backend-пакетам запрещен.

Локальные MQTT credentials для connector вводятся пользователем только в браузере и могут попадать лишь в скачиваемый локальный конфиг. Frontend не отправляет их GrowerHub.

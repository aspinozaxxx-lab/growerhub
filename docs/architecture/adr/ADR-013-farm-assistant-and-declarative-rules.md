# ADR-013: помощник, декларативные сценарии и ограниченный бюджет ИИ

Дата: 2026-10-18. Статус: принято владельцем проекта.

## Контекст

Пользователю нужен общий помощник в приложении и добровольно в Telegram: состояние фермы, фотографии, уход и создание сценариев без разработки кода. Личная авторизация Codex доступна только владельцу; публичные обращения оплачиваются отдельным ключом DeepSeek API. Автоматика должна продолжать работу при недоступности ИИ, а атака на чат не должна расходовать месячный бюджет за день.

## Решение

Расширяем существующие домены. `advisor` владеет диалогами, сообщениями, приватными изображениями, заданиями, подтверждаемыми предложениями, отчётами и квотами. `automation` владеет декларативными правилами, версиями и устойчивым исполнением. `notification` принимает разрешённые сообщения в устойчивую входящую очередь и доставляет ответы через существующую исходящую очередь. Зависимость `advisor → notification` односторонняя; notification не вызывает advisor.

Единственный источник полномочий — серверный principal. Обычные инструменты читают или меняют только его пространство через публичные Facade. Согласованное исключение: настроенный владелец с текущей активной ролью admin в реальном аккаунте получает отдельные gh_admin_* для чтения профилей, ферм и статистики системы. Проверка повторяется при каждом вызове; демо и другие администраторы этих прав не получают. Административное чтение не даёт права менять чужое оборудование, читать секреты, частные диалоги или выполнять произвольный SQL. Предложение содержит снимок версии исходных данных; отдельное действие человека подтверждает именно его. ИИ не может подтвердить своё предложение. Повтор подтверждения идемпотентен. Текст, фотографии и результаты инструментов не являются инструкциями для выдачи полномочий. Демо изолировано от реального оборудования и Telegram.

Правило версии 1 содержит имя, область, триггер, дерево условий, конечный список действий и ограничения. Поддерживаются расписание, интервал, изменение состояния, логические условия, свежесть показаний, стадия растения, гистерезис и выдержка. Действия: поддерживаемое свойство устройства, ограниченный полив, уведомление и пауза. Нет произвольного кода, сети или циклов. Существующие сценарии не мигрируют. Активный канал имеет одного автоматического владельца; конфликт блокирует активацию. Полив проходит через существующий pump и аппаратные ограничения. Состояние, ключ исполнения и шаг сохраняются до внешней команды; неизвестный результат не повторяется вслепую.

Новый технический компонент `ai_runtime` содержит два адаптера одного контракта: личный Codex app-server и DeepSeek Responses API (`deepseek-flash`, high). Отдельные процессы, системные пользователи и credentials не разделяют личную авторизацию. Runtime не имеет БД и MQTT; передаёт сообщения, tool calls, события, отмену и usage. Инструменты исполняет backend. Личный Codex не предоставляет shell, файловые операции, плагины или административные RPC. Вызовы сети происходят вне транзакций и потоков автоматизации. Доступ к runtime только через loopback и защищённый SSH-туннель. VPN и роутер не изменяются.

Квоты принадлежат advisor и задаются конфигурацией. До генерации короткая транзакция блокирует общий guard, проверяет квоты и резервирует верхнюю стоимость. Месяц UTC: $2; скользящие 24 часа: $0,15; час: $0,03; задание: $0,015. Учитываются незавершённые запросы и переход границ периода. Токены, tools, изображения, очередь и число запросов ограничены. Расчёт использует полный тариф DeepSeek Flash без скидок за кэш и время суток: $0,30 за миллион входных и $1,20 за миллион выходных токенов. Перед каждым обращением runtime ограничивает выход оставшейся суммой задания; первый вход оценивается сверху по UTF-8 с запасом на служебные токены и изображения; затем неизменный префикс опирается на подтверждённый usage, а новые результаты инструментов снова оцениваются сверху. Содержание и рассуждения между вызовами сохраняются. Неизвестная стоимость запрещает следующий вызов. Сайт и Telegram делят квоты аккаунта; гости дополнительно ограничены псевдонимным IP и подписанной браузерной сессией. Неопределённый расход сохраняет резерв, а не освобождает его. Личная подписка не является резервным провайдером для публичных запросов. Отказ ИИ не останавливает сценарии и обычные напоминания.

Публичный API расширяется в `/api/advisor/` и `/api/automation/rules/`; доступ к моделям и настройкам личного Codex разрешён только настроенному ID владельца. Поток ответа авторизуется заголовком, а не токеном в URL. Сырые provider API не публикуются. Секреты, тексты диалогов и изображения исключены из аналитики и технических журналов.

Каталог моделей и допустимые усилия личного Codex берутся из model/list; выбор сохраняется в общем диалоге приложения и Telegram. Изолированный worker раз в 6 часов получает версию установленного CLI и стабильный релиз официального npm-пакета @openai/codex. Последний результат сохраняется в assistant_guard; ошибочная проверка не означает актуальность. Уведомление о версии доступно только владельцу-администратору в настройках и через подтверждённый Telegram с дедупликацией по версии. Обновление запускает владелец-admin после подтверждения точной версии в админке; права заново проверяются по текущему аккаунту. Отдельный служебный API на loopback с собственным токеном принимает только UUID задания, текущую и последнюю стабильную версии. Root worker в отдельном systemd oneshot выполняет фиксированный операторский сценарий: закреплённый пакет, отдельный каталог, тесты и model/list, запрет новых запросов на время переключения, ожидание текущего запроса, резервная копия env и откат при неудачной проверке. Проверка включает настоящий короткий ответ без данных фермы и инструментов; откат проходит ту же проверку. UUID, этапы, резервная копия и результат сохраняются на диске; перезапуск во время переключения запускает восстановление. Отдельный SSH-forward 18789→8789 не публикуется в сети. ИИ, обычные пользователи и публичный провайдер не получают этот токен и не могут запустить обновление. Итог сохраняется в advisor и приходит владельцу в Telegram один раз.

История датчиков читается только через AutomationFacade с проверкой владельца, включая администратора вне специальных инструментов. В ответ входят период UTC, единицы, сводка по сохранённым точкам, интервалы без данных и ограниченная выборка; неизвестные значения не интерполируются. Сводка не утверждает наличие непрерывных измерений, а влажность грунта не трактуется как универсальный порог полива.

Запрос на доработку — отдельный вид подтверждаемого предложения advisor. Карточка содержит только название, задачу и ожидаемую пользу. После подтверждения сохраняется assistant_feature_requests с ID предложения, реальным аккаунтом, решением и ревизией. Гость должен войти; зарегистрированный пользователь может отправить запрос из демо. Квота заявок общая для аккаунта. Администратор читает список и принимает решение, автор видит только свои заявки. Команда получает уведомление через устойчивую очередь notification; сбой Telegram не удаляет заявку. История чата и фото не пересылаются автоматически. Заявка не запускает разработку и не является обещанием реализации.

## Последствия

Добавочные миграции сохраняют существующие сценарии, дневник и привязки Telegram. ИИ помогает настроить автоматику, но не участвует в её каждом тике. Сеть и отказ провайдера изолированы от физического управления. Публичный API включается только после настройки отдельного ключа и проверки модели. Новые интерфейсы сопровождаются проверками владения, конкуренции, неизвестных результатов, бюджетов и демо; реальные команды рабочей ферме не используются как автоматический тест.

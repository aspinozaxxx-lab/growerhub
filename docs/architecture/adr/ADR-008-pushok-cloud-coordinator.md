# ADR-008: облачное подключение ПушОк

Статус: согласовано владельцем проекта 29 сентября 2026 года.

## Контекст

Пользователь ПушОка не предоставляет GrowerHub доступ к домашней сети. На
POK100v2 с прошивкой 95 проверены регистрация нового отдельного ключа через
облако после физического нажатия кнопки, повторная авторизация и живые
обновления розетки TS011F. Home Assistant, локальный MQTT и компьютер
пользователя для этого маршрута не требуются. Проверка одного экземпляра не
подтверждает все модели устройств и безопасность автоматического полива.

## Решение

В backend добавляется технический пакет `pushok`: WebSocket-клиент облака,
криптография доступа, преобразование описаний устройств и MQTT-мост. Он
выполняется на сервере GrowerHub и не содержит расписаний или иной бизнес-логики.
Это расширение транспортной границы; существующие домены управляют устройствами
по прежнему MQTT-контракту. Отдельного приложения и второго домена устройств нет.

Домен `zigbee` владеет типом подключения, привязкой хаба к владельцу, состоянием
сопряжения и зашифрованными credentials. REST вызывает только его Facade.
Технический worker получает конфигурации через Facade и возвращает результат
сопряжения; JPA недоступна адаптеру. Ключ шифрования хранится вне БД и git.
Credentials включают отдельный ключ ПушОка и пароль MQTT координатора;
AES-GCM связывает ciphertext с UUID координатора. В REST и аналитике секретов нет.

Пользователь вводит ID хаба, подтверждает намерение подключить его, дважды
нажимает кнопку сопряжения и запускает привязку. Сервер обращается только к
заданному в конфигурации WSS-сервису ПушОка. Произвольные URL, IP и порты не
принимаются. Создание пользователя хаба допускается только во время явно
запрошенной привязки; обычное восстановление связи не регистрирует новый доступ.
Сохраняется отдельный ключ, проверяется подпись хаба и закрепляется его открытый
ключ. Одновременно хаб принадлежит одному активному координатору GrowerHub.
Не подтверждённая ключом хаба неудачная попытка освобождает ID для другого
владельца; незавершённая попытка резервирует его не более пяти минут.
Подтверждённая привязка сохраняет владение и при потере связи.

Каждый мост использует отдельные MQTT credentials и namespace координатора по
ADR-002. Он публикует metadata с `definition.exposes`, подтверждённые значения
и доступность. Команды принимает только из своего namespace, без retained
команд, очереди на время отключения и автоматического повтора неоднозначной
команды. Разрыв связи отражается как offline; подключение восстанавливается.
Преобразование параметров следует описанию драйвера хаба. Неизвестные форматы
не выдаются за управляемые возможности. Добавление и переименование Zigbee-
устройств выполняются в «Управляторе»; GrowerHub обновляет список автоматически.

Архивирование прекращает мост, отзывает MQTT credentials и удаляет серверные
секреты. Удалить отдельного пользователя непосредственно на хабе владелец может
через «Управлятор». Demo не создаёт облачных подключений. Существующие подключения
Zigbee2MQTT, настройки, история и автоматизации рабочей фермы не преобразуются.

Подключение не даёт допуска к автоматическому поливу: ADR-007 сохраняется.
Первый физический тест управления относится только к отдельной тестовой розетке.

## Последствия

Добавляется совместимая миграция и отключаемый серверный параметр. Для запуска
обязательны проверки владения, секретов, ошибочного ID, отказа сопряжения,
обрыва и восстановления связи, повторного запуска, metadata, команд, истории
и отсутствия внешних действий из демо. Пользовательский путь проверяется через
production-сервер без доступа к LAN, а инструкции и публикации описывают только
фактически проверенные возможности и зависимость от интернета и облака ПушОка.

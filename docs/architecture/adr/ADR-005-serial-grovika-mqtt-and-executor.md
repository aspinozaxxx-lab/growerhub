# ADR-005: серийная Grovika с отдельными MQTTS credentials

Статус: принято

## Контекст

Grovika подключалась к общему MQTT endpoint без TLS и с общей зашитой учётной записью. Production принимает внешние подключения только через MQTTS `8883`, поэтому устройство не появлялось в GrowerHub. Общий секрет нельзя безопасно печатать на коробке или вводить пользователю. Одновременно локальный RTC и выполнение расписаний в firmware дублировали backend automation и усложняли устройство.

## Решение

- При серийной подготовке `device_id` формируется из eFuse MAC в существующем формате `GROVIKA_XXXXXX`, печатается на коробке и показывается в локальном web UI.
- Admin-only provisioning API создаёт непривязанное устройство и отдельный Mosquitto Dynamic Security client. Username и фиксированный client ID равны `device_id`; ACL ограничен `gh/dev/<device_id>/#`, а wildcard подписки проверяются типами `subscribePattern`/`unsubscribePattern`.
- Для устройства генерируется 256-битный пароль. Backend хранит только SHA-256 и время подготовки, а открытое значение один раз передаётся фабричному скрипту и записывается в LittleFS. Ротация требует явного флага, удаление устройства отзывает client и роль.
- Backend при старте восстанавливает полный ACL ранее подготовленных устройств через `modifyRole` без ротации секрета. Firmware периодически повторяет подписку на собственный cmd topic, чтобы изменение ACL применилось после временного отказа подписки.
- Firmware подключается только к `growerhub.ru:8883` через TLS с ISRG Root X1. Валидное сетевое UTC требуется для проверки сертификата; MQTT не запускается при отсутствующей или повреждённой `/cfg/mqtt.json`. Секрет не попадает в web UI и логи.
- Пользователь привязывает Grovika только по напечатанному `device_id`. Свободное устройство назначается атомарно, повтор собственного ID идемпотентен, чужое устройство возвращает явный конфликт и не перепривязывается.
- После десяти неудачных корректно сформированных ID аккаунт блокируется на 60 минут. Затем до успешной новой привязки разрешены две попытки в скользящий час. Успех для ранее свободного устройства удаляет историю ограничений.
- Grovika является исполнительным устройством. Backend выполняет календарные сценарии, firmware исполняет команды, публикует датчики и применяет локальные аппаратные ограничения. RTC, локальная конфигурация сценариев и локальные расписания удаляются. Длительность работы насоса отсчитывается монотонным таймером и не зависит от сети или абсолютного времени.
- Публичный `1883`, общий пароль устройств и временный legacy-брокер не используются.

## Последствия

- Заводской процесс требует административный access token, доступ к USB-порту и однократную запись уникального LittleFS после общей прошивки.
- Потерянный пароль нельзя прочитать из backend: устройство проходит явную ротацию и повторную запись LittleFS.
- Пользователь не работает с MQTT-секретами; для добавления достаточно ID с коробки или web UI устройства.
- Работа расписаний требует доступности backend, но уже принятая команда насоса безопасно завершается локально даже при потере сети.
- ADR-002 больше не разрешает временный MQTT `1883` для Grovika.

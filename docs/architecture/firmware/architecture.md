# Firmware

Firmware является исполнительным контуром Grovika: читает датчики, управляет реле, публикует state и service events и принимает команды через MQTT. Решения автоматизации и календарные расписания выполняет backend.

## Структура

- `src/app` - точка сборки приложения.
- `src/core` - runtime, context, event queue, scheduler и базовый интерфейс module.
- `src/modules` - прикладные модули устройства.
- `src/services` - Wi-Fi, MQTTS, storage, сетевое UTC, OTA, web config и device identity.
- `src/drivers` - драйверы DHT, soil и relay.
- `src/config` - build flags, hardware profile и pin map.
- `src/util` - JSON, logging и MQTT codec.
- `test` - unit-тесты PlatformIO.

## Модули

- `StateModule` формирует и публикует state.
- `CommandRouterModule` обрабатывает MQTT-команды и ACK.
- `ActuatorModule` управляет насосом, светом и состоянием ручного полива.
- `SensorHubModule` сканирует порты и читает датчики.
- `OtaModule` устанавливает OTA, сообщает этапы и управляет rollback.

## Контракты

Firmware использует системный MQTT-контракт state, ack и service events из `docs/architecture/architecture.md`. Каждая сборка публикует в state свой `hw_profile`: `esp32dev` либо `esp32c3_supermini`.

Серийная подготовка формирует `device_id` вида `GROVIKA_XXXXXX` из последних трёх байт eFuse MAC, получает одноразовый пароль через административный API и записывает `/cfg/mqtt.json` в LittleFS. Локальная Wi-Fi точка доступа называется ровно как `device_id`, без дополнительного префикса. Локальный web UI показывает тот же приоритетный список Wi-Fi, который использует устройство: пользовательский `/cfg/wifi.json` либо встроенные сети при отсутствии пользовательской конфигурации. Пароль MQTTS не показывается в web UI и логах. Без корректной конфигурации MQTTS не запускается; web UI показывает `device_id`, endpoint и диагностическое состояние подключения.

Соединение использует `WiFiClientSecure`, `growerhub.ru:8883` и встроенный корневой сертификат ISRG Root X1. NTP нужен только для проверки TLS-сертификата и UTC-меток телеметрии. Аппаратного RTC и локальных календарных расписаний нет. Длительность команды `pump.start` отсчитывается монотонно через `millis()` и ограничивается аппаратным максимумом, поэтому остановка насоса не зависит от сети или абсолютного времени.

Во время работы насоса runtime продолжает обслуживать MQTTS до и после прохода модулей, поэтому `pump.stop` принимается тем же неблокирующим контуром. Подписка на собственный cmd topic восстанавливается при каждом соединении и периодически повторяется после временного отказа broker ACL. Переходы запуска и остановки вызывают немедленную публикацию retained state; неуспешная публикация повторяется с ограниченной частотой. Активный опрос soil и DHT на время полива приостанавливается, но heartbeat продолжает передавать последнее известное состояние. Для обоих аппаратных профилей мощность Wi-Fi TX ограничена 15 dBm, чтобы снизить пиковый ток контроллера; это не заменяет отдельное питание насоса и электрическую защиту от помех исполнительной цепи.

OTA выполняется только по MQTT-команде с URL GrowerHub, версией, SHA-256 и
`correlation_id`. `OtaInstaller` допускает только точный HTTPS-prefix
`https://growerhub.ru/firmware/` и имя, оканчивающееся на аппаратный профиль
текущей сборки, проверяет TLS через ISRG Root X1, записывает неактивный
OTA-раздел и до активации сравнивает SHA-256 всего бинарника.
Обновление отклоняется при работающем насосе. После публикации `downloading`
устройство закрывает MQTTS transport перед HTTPS-загрузкой, чтобы две TLS-сессии
не конкурировали за память. После установки MQTT восстанавливается: ошибка или
этап `restarting` повторяются до успешной публикации; при недоступном broker
успешно записанная прошивка перезапускается по защитному таймауту.
Новая прошивка подтверждает boot только после восстановления MQTTS; иначе
используется rollback ESP32.
